# 관리자 회원 관리

- 기준일: 2026-08-04
- 화면: `/admin/` → `회원`
- DB 마이그레이션: `supabase_v50.sql`, `supabase_v52.sql`
- 서버 경로: `POST /api/admin/members/action`

## 운영 정책

현재는 PASS 같은 유료 본인인증을 의무화하지 않습니다. 거래 플랫폼을 열기 전까지는
이메일 인증을 마친 가명 계정을 기본으로 운영하고, 공개 화면에는 이메일·실명·전화번호를
노출하지 않습니다. 이름과 연락처는 계정 복구와 운영 대응에 필요한 범위를 확정한 뒤
일반 가입 재개 시점에 다시 결정합니다.

회원의 서비스 권한과 관리자 권한은 서로 다른 개념입니다.

| 구분 | 값 | 의미 |
|---|---|---|
| 회원 권한 | 일반, 프리미엄 | 계산기·케어로그의 유료 기능 사용 범위 |
| 관리자 권한 | 부관리자, 최고관리자 | 운영 화면과 개인정보 접근 범위 |
| 계정 상태 | 정상, 이용 제한 | 로그인·세션 갱신 가능 여부 |

프리미엄을 `일반`으로 변경하면 관리자가 수동으로 부여한 프리미엄만 회수합니다.
결제나 프리미엄 코드로 받은 유효 권한까지 임의로 없애지는 않습니다.

## 최고관리자가 할 수 있는 작업

- 이메일·이름·닉네임·연락처·가입 수단·가입일·최근 로그인·이메일 인증 여부 조회
- 정상/이용 제한, 일반/프리미엄, 관리자 계정 필터와 검색
- 관리자 수동 프리미엄 부여와 회수
  - 체험판: 기본 7일, 1~3650일
  - 기간제: 기본 30일, 1~3650일
  - 무기한: 종료일 없음
- 회원 이용 제한과 제한 해제
- 회원 요청 또는 운영 사유에 따른 탈퇴 처리
- 현재 필터 결과 CSV 내보내기

모든 변경에는 2~500자의 사유가 필요합니다. 프리미엄 부여 기록에는 부여 유형, 기간,
시작일, 만료일, 부여한 최고관리자가 함께 저장되며 작업 기록은
`private.admin_member_actions`에 남습니다. 현재 로그인한 최고관리자 본인과 관리자 계정은
회원 탭에서 제한하거나 삭제할 수 없습니다. 관리자 권한 변경은 별도 `관리자` 탭에서만 합니다.

## 보안 경계

브라우저에는 Supabase 공개 키만 있습니다. 회원 권한 변경과 탈퇴는 Cloudflare Worker가
로그인 토큰을 다시 검증하고 `my_admin_role()` 결과가 `owner`인지 확인한 뒤 실행합니다.
Supabase Secret Key는 Worker secret으로만 저장하며 정적 파일·Git·브라우저 응답에 넣지 않습니다.
로그인 사용자의 JWT 검증 요청은 공개용 publishable key와 사용자 토큰을 함께 사용하고,
관리자 전용 변경 요청만 서버의 Secret Key를 `apikey`로 사용합니다. 셸에서 복사할 때 생길 수 있는
BOM·줄바꿈 문자는 Worker에서 제거한 뒤 헤더를 구성합니다.

이용 제한은 Supabase Auth의 장기 ban을 사용합니다. 이미 발급된 access token은 만료 전까지
강제로 폐기할 수 없으므로 일반 가입을 열기 전에 Supabase Auth의 JWT expiry를 15분으로
설정해야 합니다. ban은 새 로그인과 세션 갱신을 막고, 기존 토큰은 최대 15분 안에 끝납니다.

탈퇴는 다음 순서입니다.

1. 최고관리자가 최근 30분 안에 다시 로그인했는지 확인
2. 대상이 본인 또는 관리자 계정이 아닌지 서버에서 확인
3. 대상 계정을 먼저 이용 제한
4. 동의 기록 익명 보관, 사진·케어·브리딩·프로필 데이터 정리
5. Supabase Auth Admin API로 사용자 삭제
6. 최종 작업 기록 저장

5단계가 실패하면 계정은 제한된 채 남아 재시도할 수 있습니다. 결제 기록은 회계·분쟁 대응을
위해 사용자 식별 연결만 끊고 거래 행 자체는 보존하도록 v49 외래 키가 구성되어 있습니다.

## 적용 순서

1. Supabase SQL Editor에서 `supabase_v50.sql`, `supabase_v52.sql` 순서로 실행
2. Cloudflare Worker secret 등록

   `npx wrangler secret put SUPABASE_SECRET_KEY`

3. Supabase Dashboard → Authentication → Settings에서 JWT expiry를 900초로 설정
4. 테스트 일반 회원 계정으로 아래 시나리오 확인
   - 체험판·기간제·무기한 프리미엄 부여 → 유형·만료일·회원 화면 권한 확인
   - 일반으로 변경 → 관리자 수동 부여분 해제 확인
   - 이용 제한 → 새 로그인과 토큰 갱신 실패 확인
   - 제한 해제 → 로그인 복구 확인
   - 테스트 회원 탈퇴 → Auth·프로필·개체·사진 삭제와 동의 기록 익명 보관 확인
5. 확인 후 Cloudflare 배포

2026-08-04 라이브 검수에서 일반 테스트 계정에 7일 체험판을 부여해 만료일·부여 경로·감사 기록을
확인한 뒤 일반 권한으로 복구했습니다. 해당 배포의 전체 회귀 테스트는 312개를 통과했습니다.

`SUPABASE_SECRET_KEY`는 `wrangler.jsonc`, `.dev.vars`, 정적 JS 또는 문서에 실제 값을 적지 않습니다.

## 아직 열지 않는 기능

- 일반 회원가입과 비밀번호 재설정
- PASS 등 휴대전화 본인인증
- 회원 간 거래·결제 중개
- 신고 누적에 따른 자동 제한
- 관리자 작업 기록 조회·보존 기간 자동 정리 화면
- 소셜 로그인 provider 연결 해제까지 포함한 완전 자동 탈퇴

거래 기능을 열거나 사기 피해 대응을 서비스 책임 범위에 넣을 때 본인인증·신고·분쟁 처리
정책을 다시 검토합니다.
