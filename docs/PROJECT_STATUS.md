# 프로젝트 현재 상태와 다음 작업

- 기준일: 2026-08-02
- 라이브: <https://ryangstudio.com/>
- 배포 대상: Cloudflare Workers 정적 자산
- 데이터베이스: Supabase, `supabase_v32.sql`까지 적용

이 문서는 현재 라이브 상태와 다음 작업 순서를 빠르게 확인하기 위한 기준 문서입니다.
세부 설계의 배경은 `STUDIO.md`, `AUTH.md`, `plans/linebreeding-goal-roadmap.md`를 함께 봅니다.

## 현재 공개 범위

- 모프 계산기: 레오파드게코, 크레스티드게코, 팻테일게코, 볼파이톤
- 크리처 케어로그와 브리딩 관리: 테스트 잠금 안에서 운영
- 일반 회원가입·비밀번호 재설정: 일시 중단
- 이용약관·개인정보처리방침 링크와 광고 영역: 일시 숨김
- 공개 개체 갤러리 진입점: 일시 숨김

숨김은 화면만의 조치가 아닙니다. 신규 Auth 사용자 생성은 DB 트리거로도 막고,
계정 데이터 API는 인증 사용자로 제한합니다. 공개 개체 조회 RPC만 익명 접근을 유지합니다.

## 완료된 기능

### 모프 계산기

- 4종 계산기와 종별 검색
- 비주얼·헷·복수 100% 헷 표기
- 유전 근거 보기와 건강·난임 주의
- 계산 기록·즐겨찾기 저장소
- 계획 도구는 공개 계산기에서 분리하고 브리딩 관리의 분석 탭으로 이동
- 화이트앤옐로우(WY), 느와르, 크레스티드 파이드 등 현재 확정 데이터 반영

### 크리처 케어로그

- 개체·프로필 사진·추가 사진 3장 관리
- 업로드 전 크롭 위치·확대 조정
- 급여·물·배변·탈피·거식·청소·건강·메모·체중 기록
- 반복 계획, 오늘 할 일, 캘린더 파일 내보내기
- 혈통, 최근 기록, 공유용 공개 프로필과 QR
- 오늘·개체·계획·먹이·건강·요약과 개체 상세·공개 프로필·갤러리의
  한국어·영어·중국어·일본어 지원
- 날짜·숫자·오류·ARIA·공유 URL·캘린더 내보내기의 선택 언어 유지

### 브리딩 관리

- 레오파드·크레스티드·팻테일·볼파이톤 종별 개체·페어링·클러치 분리
- 형질별 1~5 관찰 평가
- 유전 모프 역산과 라인 고정·두 라인 크로스 프로젝트
- 등록 개체 기반 부모 추천, 최대 3세대 관계 주의, 조건부 3단계 로드맵
- 프로젝트 → 페어링 → 등록 새끼 선발 후보 연결
- 계산 기록·클러치 예상·페어링 비교 분석
- 한국어·영어·중국어·일본어 및 언어가 유지되는 화면 이동

### 데이터·보안

- `supabase_v31.sql`: 브리딩 프로젝트, 형질별 평가, 프로젝트 소유권 검증
- `supabase_v32.sql`: 클러치 종 필수화, 페어링 소유자·종 일치 트리거
- 개인 사진 버킷 비공개와 서명 URL
- 계정별 RLS, 공개 RPC 최소화, 업로드 MIME·크기 제한
- 브리딩 v32 배포 기준 테스트 151개 통과
- 케어로그 I18n과 폐쇄 베타 잠금 화면까지 포함한 현재 전체 회귀 테스트 164개 통과

## 다음 작업 순서

### P0 — 폐쇄 베타 완성

1. 실제 계정으로 전체 흐름 재검수
   - 개체 → 계획·기록 → 브리딩 프로젝트 → 페어링 → 클러치 → 새끼
2. 영어·중국어·일본어 실제 계정에서 사진 크롭·공유 QR·캘린더 파일 재검수
3. 계정·로그인 화면 4개 언어와 로그인 뒤 선택 언어 복귀
4. 프로젝트 문서와 라이브 동작의 지속 동기화

### P1 — 실제 부화 결과

1. 유정란·무정란·중지란과 실제 부화일·부화 수 기록
2. 부화 개체를 클러치와 부모에 연결
3. 예상 분포와 실제 결과를 보장 표현 없이 비교
4. 부화 개체를 라인브리딩 프로젝트의 다음 세대 후보로 연결

이 단계는 새 칼럼과 소유권 검증이 필요하므로 `supabase_v33.sql`로만 추가합니다.
이미 적용된 마이그레이션 파일은 수정하지 않습니다.

### P2 — 계산기와 운영 보완

- 내 등록 개체를 계산기 부모 프리셋으로 불러오기
- 모바일 고정 계산 버튼과 긴 모프 목록 접기
- 모프 정보 카드, 건강 근거, 자료 출처와 갱신일
- 관리자 케어 통계, 배포·백업·오류 모니터링
- 케어 UI 모듈을 화면 책임별로 더 작게 분리해 유지보수성 개선
- 방문 통계에 케어 화면의 선택 언어 함께 기록
- 선택적 COI 계산은 혈통 정확도 안내와 함께 별도 설계

### P3 — 계정 공개와 수익화

- 초대 계정 기반 폐쇄 베타 후 일반 가입 재검토
- 로그인 수단 연결·해제, 마지막 수단 보호, provider 탈퇴 정리
- 카카오 이메일 미제공·미검증 및 중복 계정 대응
- iOS 앱에서 카카오·Google을 제공할 경우 Apple 로그인 동시 검토
- 결제 entitlement, 서버 검증, webhook 재시도·중복 방지
- 이용약관·개인정보처리방침·환불 정책을 완성한 뒤 다시 노출

## 유지 원칙

- 공개 모프 계산기에는 계산에 필요한 기능만 둡니다.
- 장기 프로젝트·크로스·선발·실제 결과는 브리딩 관리가 소유합니다.
- 멘델 확률과 라인브리딩 관찰 평가는 섞지 않습니다.
- 새 사용자 문구는 한국어·영어·중국어·일본어를 함께 추가합니다.
- 케어로그 I18n은 `care-i18n-ko/en/zh/ja.js`의 동일 키 계약과
  `care-i18n.js`의 공통 날짜·숫자·URL 경계를 사용합니다.
- DB 변경은 새 순번 마이그레이션과 `supabase_setup.sql`을 같이 갱신합니다.
- 인증·결제 권한은 화면이 아니라 Supabase RLS·트리거·서버 경계에서 검증합니다.
