# 파충류 모프 계산기 — 앱인토스 미니앱

레오파드 게코 · 크레스티드 게코 · 펫테일 게코 · 볼파이톤 계산기를 **미니앱 한 개**로
묶은 것입니다. 이 폴더에는 앱인토스에서만 다른 부분(허브 화면, 라이트 고정)만 있고,
계산 엔진은 `gecko/` · `crested/` · `fattail/` · `ballpython/` 원본을 그대로 씁니다.

```bash
python3 tools/build_toss.py     # dist-toss/ 생성 → 이걸 올립니다
```

---

## 왜 네 개가 아니라 하나인가

취향이 아니라 정책입니다. 앱인토스 서비스 오픈 정책의 어뷰징 방지 조항:

> 동일 워크스페이스 내에서 **이미 등록된 미니앱과 완전히 다른 목적의 기능만** 새로운
> 미니앱으로 등록할 수 있어요. 테마·대상·주제만 다른 경우는 별도 미니앱으로 인정하지
> 않습니다. 동일 브랜드로 여러 미니앱을 반복 출시해 노출을 점유하는 행위도 제한됩니다.
>
> 위반 시: 콘텐츠 수정 요청 → 미노출 처리 → 등록·운영 제한
>
> — https://developers-apps-in-toss.toss.im/ (서비스 오픈 정책)

네 계산기는 **핵심 기능이 같고(부모 형질 → 멘델 확률) 종만 다릅니다.** 정확히 "주제만
다른 경우"입니다. 따로 올리면 반려 대상이고, 통과하더라도 종을 늘릴 때마다 새 앱을
낼 수 없습니다. 하나로 두면 다음 종은 허브에 카드 한 장 추가하는 업데이트가 됩니다.

곁가지 이득도 있습니다 — 심사를 네 번이 아니라 한 번 받고, 토스 안에서 "모프 계산기"로
검색했을 때 후보가 갈리지 않고, 여러 종을 함께 키우는 사람이 앱을 오가지 않습니다.

**케어로그(`care/`)는 이야기가 다릅니다.** 사육 기록은 계산기와 목적도 핵심 기능도
달라서 별도 미니앱으로 낼 수 있습니다. 다만 로그인이 필요한데 앱인토스는 **토스 로그인만**
허용하므로, 지금의 Supabase 이메일·구글 로그인을 그대로 옮길 수 없습니다. 이 번들에는
넣지 않았습니다.

## 왜 SPA 가 아니라 종별 페이지인가

허브에서 종을 고르면 그 종의 페이지로 **이동**합니다. 한 화면에서 종만 바꾸는 방식이
아닙니다. 네 코어가 전부 같은 이름을 `const` 로 잡고 있기 때문입니다.

```js
// gecko-core.js · crested-core.js · fattail-core.js · ball-core.js 모두
const SERVICE_ID = ...;
function gName(g){...}   function gSuper(g){...}   function tr(o){...}
```

둘을 한 페이지에 올리는 순간 `Identifier 'SERVICE_ID' has already been declared` 로
멈춥니다. 한 화면에서 종을 바꾸려면 네 코어를 ES 모듈이나 IIFE 로 감싸야 하는데,
그건 웹사이트 쪽 네 파일을 전부 손대는 일입니다. 페이지를 나누면 원본을 한 글자도
건드리지 않고 같은 결과를 얻습니다.

## 폴더

```
toss/                     ← 소스 (이 폴더만 손으로 고칩니다)
  index.html              종 선택 허브
  hub.css                 허브 전용 스타일
  toss-light.css          라이트 모드 고정 (계산기 CSS 의 다크 블록을 덮음)
  README.md

tools/build_toss.py       위 소스 + 계산기 원본 → dist-toss/ 조립
dist-toss/                ← 제출용 결과물 (git 에 안 들어갑니다. 매번 새로 만드세요)
```

`dist-toss/` 를 직접 고치지 마세요. 다음 빌드에서 통째로 지워집니다.

빌드가 원본에서 무엇을 걷어내고 무엇을 덧붙이는지는 `tools/build_toss.py` 머리말에
이유와 함께 적어 두었습니다. 요약하면 — 검색엔진 메타, Supabase 접속, 볼파이톤
비밀번호 잠금, 앱 밖으로 나가는 링크, 쿠키 안내 바, 광고 자리를 빼고, 라이트 모드
고정을 넣습니다.

### 원본을 고칠 때 주의

- **팔레트를 바꾸면** `toss-light.css` 의 같은 변수도 바꿔야 합니다. 안 그러면 앱에서만
  색이 다른 화면이 됩니다.
- **`<종>-ui.js` 가 새 DOM 요소를 확인 없이 만지게 되면**(`getElementById(x).어쩌고`)
  빌드가 그 요소를 지우고 있는지 확인하세요. 지금은 `#mailLink` · `#adSlot` ·
  `#donateBtn` 이 그런 경우라 '지우기' 대신 '숨기기'로 처리해 두었습니다.
- **`AD_ENABLED` 같은 스위치의 문구가 바뀌면** 빌드가 `빌드 중단` 을 내며 멈춥니다.
  조용히 넘어가지 않게 일부러 그렇게 해 두었습니다. `CORE_PATCHES` 를 고쳐주세요.

## 심사 기준 대비 현황

앱인토스 비게임 출시 체크리스트 기준입니다.

| 항목 | 상태 |
|---|---|
| 라이트 모드 | ✅ `toss-light.css` 로 고정. 기기가 다크여도 라이트로 뜹니다 |
| 로그인 (토스 로그인만 허용) | ✅ 로그인 자체가 없습니다 |
| 결제 (토스페이·인앱결제만) | ✅ 결제 없음. 후원 버튼·프리미엄 UI 제외 |
| 인앱 광고 (앱인토스 광고만) | ✅ 외부 광고 없음. `AD_ENABLED` 를 꺼서 자리도 안 잡습니다 |
| 외부 링크 제한 | ⚠️ 업데이트 노트 모달과 개인정보처리방침에 `mailto:` 가 남아 있습니다. 문의처 안내라 남겼습니다. 지적받으면 링크를 떼고 주소만 글자로 두면 됩니다 |
| eval 금지 | ✅ 없음 |
| CSR/SSG 만 허용 | ✅ 순수 정적 파일 |
| 자동 바텀시트 금지 | ✅ 쿠키 안내 바 제거. 업데이트 노트는 버튼을 눌러야 열립니다 |
| 자사 앱 설치 유도 금지 | ✅ 스튜디오 홈 링크 제거 |
| 생성형 AI 고지 | ✅ 해당 없음 |
| 반응 지연 2초 미만 | ⚠️ 계산은 즉시. 다만 히어로 이미지가 큽니다(아래 참고) |
| 비게임 내비게이션 바 | ❌ **미구현** — SDK 연동 필요 |
| 사용자 식별키 발급 | ❌ **미구현** — 저장할 데이터가 없어서 필요한지 확인 필요 |

## 남은 일

1. **앱인토스 SDK 연동** — 비게임 내비게이션 바(뒤로가기·홈)는 필수 항목입니다.
   콘솔에서 앱을 등록해야 키가 나오므로 그다음 순서입니다.
   가이드: `ai-vibe-coding/tutorials/webview.md` (기존 웹 프로젝트에 SDK 연동하기)
2. **약관 손보기** — `terms.html` 은 스튜디오 전체(로그인·프리미엄·광고·케어로그) 기준으로
   쓰여 있습니다. 이 미니앱에는 없는 기능을 약관이 설명하고 있는 상태라, 앱인토스판으로
   줄여야 합니다. 빌드는 '돌아가기' 링크와 canonical 만 고칩니다 — 문장은 손대지 않습니다.
3. **이미지 줄이기** — 번들 2.8MB 중 1.4MB 가 히어로 PNG 네 장입니다. WebP 로 바꾸거나
   허브용 축소본을 따로 두면 첫 화면이 훨씬 빨라집니다.
4. **CDN 두 개 검토** — Pretendard 와 bootstrap-icons 를 jsDelivr 에서 받습니다.
   토스가 자체 폰트를 제공하므로 폰트는 뺄 수 있고, 아이콘은 쓰는 것만 골라
   번들에 넣는 편이 안전합니다.
5. **다국어를 남길지 결정** — 지금은 한·영·일·중 4개국어 버튼이 그대로 있습니다.
   앱인토스는 국내 만 19세 이상에게만 제공되므로, 빼면 화면이 단순해집니다.
6. **콘솔 등록 → 심사** — 등록 후 초기 검토 영업일 1~2일, QR 테스트 후 출시 검토
   영업일 최대 3일.
